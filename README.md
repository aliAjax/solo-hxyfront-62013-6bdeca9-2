# 跨建筑古建修缮排程台

面向古建筑修缮团队的跨建筑排程前端：管理人员从多处在修古建中选取**病害构件**，
系统生成包含**工序链、工期、班组、预算**的修缮方案，并对方案做五类硬校验：

1. **班组资质** —— 班组所持工种资质必须与工序要求一致；**未指派班组即阻断**，新版本不得缺少必要班组；
2. **跨项目占用** —— 班组在其他文保项目的占用区间不可排入；
3. **资源重复占用** —— 同一班组不得在同一时段承担两道工序；
4. **工序依赖 / 工期冲突** —— 后序不得早于前序完工（依赖倒置），依赖成环可被定位；**未排定开工日同样阻断**；
5. **预算上限** —— 直接费 + 综合管理费不得超过预算上限。

所有冲突均**定位到具体工序**（甘特图红色斜纹任务条 + 问题清单「定位到工序」双向联动）。

## 核心交互

- **自动排程**：按工序依赖拓扑排序，结合班组资质日历与跨项目占用贪心排定；
- **手工调整**：甘特行内直接修改开工日或更换班组，改动先进入**待提交区**，不影响当前版本；
- **待提交区**：可逐项撤销、**整体放弃**（恢复已提交版本）或**确认提交**；
- **排程版本**：确认提交产生不可变新版本（v1、v2…），右侧保留完整版本历史；
- **并发冲突**：多人同时修改同一方案时，后提交者基于过期版本会被乐观锁阻止，
  弹出版本冲突提示并**自动保留个人草稿**（草稿仅创建人本人可见、可套用、可删除，
  切换到其他身份后他人草稿不可见也不可操作），可一键把草稿重放到他人最新版本之上重新校验。

## 覆盖场景（顶栏一键演示）

| 场景 | 说明 |
| --- | --- |
| 场景1 · 依赖倒置 | 把油饰工序提前到前序完工之前，定位工序倒置冲突 |
| 场景2 · 资源重复占用 | 两道工序同一时段占用同一木作班 |
| 场景3 · 超出预算 | 压低预算上限触发预算红线 |
| 场景4 · 放弃调整 | 多项调整进入待提交区后整体放弃 |
| 场景5 · 并发版本冲突 | 本人持有调整时他人先提交，触发版本冲突并保留草稿 |

## 架构（依赖倒置）

```
src/
  domain/        领域层：类型、种子数据、排程引擎、规则校验（纯函数，无框架依赖）
  application/   端口（SchedulerPort / ValidatorPort / PlanRepositoryPort）
                 与应用服务 ScheduleService；只依赖抽象，不依赖具体实现
  infra/         适配器：LocalPlanRepository（localStorage 持久化）
  ui/            React 组件：构件选取、甘特排程台、校验/预算/待提交/版本/草稿面板
```

`application/container.ts` 是唯一的**组合根**：在此选择具体适配器并注入服务，
替换排程算法、规则引擎或存储后端时无需改动应用服务与 UI。

## 技术栈

React 19 + Vite + TypeScript，本地运行、localStorage 持久化，无后端依赖。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62013（`npm run build` 可做生产构建校验）。
